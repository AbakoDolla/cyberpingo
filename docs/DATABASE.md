# CyberPingo Database

Engine: **PostgreSQL 16**. ORM: **Prisma**.
Schema: `apps/api/prisma/schema.prisma`.

## 1. Local setup

```bash
docker compose up -d          # PostgreSQL on localhost:5432
cp apps/api/.env.example apps/api/.env
pnpm db:generate              # generate the Prisma client
pnpm db:migrate               # create and apply the development migration
```

Default local credentials (development only, defined in `docker-compose.yml`):
user `cyberpingo`, password `cyberpingo`, database `cyberpingo`.

## 2. Models (V1)

| Model                 | Purpose                                        |
| --------------------- | ---------------------------------------------- |
| `User`                | Platform account, XP and level                 |
| `Course`              | Learning path                                  |
| `Lesson`              | Ordered unit of a course                       |
| `Quiz`                | Quiz attached to a lesson                      |
| `QuizQuestion`        | Question with choices and the correct index    |
| `Challenge`           | Hands-on exercise, optionally tied to a lesson |
| `ChallengeSubmission` | A user's attempt at a challenge                |
| `Progress`            | Per-user course/lesson progression             |
| `Badge`               | Badge catalogue                                |
| `UserBadge`           | Badge earned by a user                         |

### Relations

```text
User
 ├── Progress            (1-n)
 ├── ChallengeSubmission (1-n)
 └── UserBadge           (1-n)

Course
 └── Lesson              (1-n)

Lesson
 ├── Quiz                (1-n)
 ├── Challenge           (1-n, optional link)
 └── Progress            (1-n)

Quiz
 └── QuizQuestion        (1-n)

Badge
 └── UserBadge           (1-n)
```

### User

| Column         | Type       | Notes                           |
| -------------- | ---------- | ------------------------------- |
| `id`           | `String`   | `cuid()` primary key            |
| `username`     | `String`   | **unique**                      |
| `email`        | `String`   | **unique**                      |
| `passwordHash` | `String`   | scrypt hash, never exposed      |
| `avatar`       | `String?`  | URL                             |
| `xp`           | `Int`      | default `0`, backend-controlled |
| `level`        | `Int`      | default `1`, derived from XP    |
| `createdAt`    | `DateTime` | default `now()`                 |
| `updatedAt`    | `DateTime` | `@updatedAt`                    |

## 3. Fields never exposed by the API

| Model          | Field          | Reason                       |
| -------------- | -------------- | ---------------------------- |
| `User`         | `passwordHash` | Credential material          |
| `QuizQuestion` | `correctIndex` | Would leak the answer        |
| `Challenge`    | `solutionHash` | Would leak the expected flag |

Services must select explicit fields (or map to the `packages/types` shapes)
instead of returning raw Prisma records.

## 4. Conventions

- Primary keys: `String` `cuid()`.
- Table names are snake_case via `@@map`; Prisma models stay PascalCase.
- Enums are uppercase (`BEGINNER`, `COMPLETED`, ...) and mirrored in
  `packages/types`.
- Every foreign key has an explicit `onDelete` behaviour.
- Frequently filtered foreign keys are indexed.
- Timestamps: `createdAt` (`@default(now())`) and `updatedAt` (`@updatedAt`).

## 5. Migrations

```bash
pnpm db:migrate                       # development: create + apply
pnpm --filter @cyberpingo/api db:deploy   # CI/production: apply only
pnpm db:studio                        # inspect data
```

Rules:

- Migrations are committed to Git (`apps/api/prisma/migrations/`).
- Never edit an applied migration; create a new one.
- `prisma db push` is reserved for throwaway local experiments.
- The first migration is generated by the backend developer once a PostgreSQL
  instance is available; the foundation ships the schema only.

## 6. Out of scope for V1

`Comment`, `Team`, `Organization`, `Payment`, `Subscription`, `Certificate`,
`Notification`, `Marketplace` and AI-related models belong to later versions.
